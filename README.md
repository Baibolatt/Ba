# PartsHub

Демонстрационный сайт оптового склада автозапчастей. Каталог, категории, товары,
заказы, поиск и аккаунты клиентов читаются из SQLite через Prisma. Корзина и
избранное пока работают в браузере. Оформленный заказ сохраняется в базе вместе
с контактами, способом получения и ценой товаров на момент заказа; клиент может
зарегистрироваться по номеру телефона, войти и видеть только свои заказы.
Онлайн-оплата не подключена. В админку `/admin` вход по общему паролю из `ADMIN_PASSWORD`: там
меняются статусы заказов, остатки товаров и импорт прайс-листов из Excel/CSV.

## Стек

- Next.js 16 (App Router) и React 19
- TypeScript в строгом режиме
- Tailwind CSS v4, дизайн-токены в `src/app/globals.css`
- Prisma 7, SQLite и драйвер `better-sqlite3`
- SheetJS (`xlsx`) для .xlsx/.xls и `iconv-lite` для CSV в Windows-1251
- Внешних UI-библиотек нет: иконки, компоненты и заглушки изображений свои

## Запуск

```bash
npm install
npm run db:setup
npm run dev
```

`npm run db:setup` — одна команда, которая поднимает базу с нуля: применяет
миграции, создаёт `prisma/dev.db` и запускает seed с тестовыми данными.
Повторный запуск пересоздаёт демо-данные. Если файла `.env` нет, используется
путь по умолчанию `file:./prisma/dev.db`; пример переменных — в `.env.example`.

Для входа в админку задайте в `.env` переменную `ADMIN_PASSWORD`. Без неё
страница `/admin/login` сообщает, что пароль не настроен, а панель недоступна.
Смена пароля завершает все открытые админ-сессии. Для подписи клиентских сессий
можно задать отдельный `SESSION_SECRET`; если он не задан, используется
`ADMIN_PASSWORD`.

Сайт откроется на [http://localhost:3012](http://localhost:3012).

Дополнительные команды:

```bash
npm run db:migrate       # новая миграция после изменения schema.prisma
npm run db:seed          # только тестовые данные
npm run db:studio        # Prisma Studio
npm run generate:samples # пересоздать 4 тестовых прайс-листа
npm run test:import      # проверить импорт на временной SQLite
```

Сборка и запуск production-версии:

```bash
npm run build
npm start
```

При сборке страницы читают данные из базы, поэтому сначала выполните
`npm run db:setup`.

## Каталог и поиск

- Фильтры, сортировка, вид и страница каталога хранятся в URL: `brand`
  (можно несколько), `min`, `max`, `stock=1`, `sort`, `view=table`, `page`;
  ссылка с параметрами воспроизводит ту же выдачу
- Фильтрация, сортировка и пагинация выполняются в Prisma: `count` для общего
  числа и `findMany` с `skip`/`take`, по 8 товаров на страницу. Бренды в боковой
  панели считаются в рамках выбранной категории
- Некорректные параметры игнорируются; если `min` больше `max`, они меняются
  местами; номер страницы больше последней ограничивается последней
- Цена в фильтре применяется по Enter или потере фокуса, бренд и наличие — сразу;
  переключение категории и сброс фильтров очищают параметры
- Поиск `/search?q=...` ищет по названию, артикулу, бренду, категории, описанию,
  совместимости и характеристикам; артикул сравнивается без учёта регистра,
  пробелов и дефисов. SQLite не умеет регистронезависимый поиск по кириллице,
  поэтому небольшой каталог дофильтровывается в приложении

## База данных

- `Category` и `Brand` — отдельные таблицы, у товара внешние ключи на бренд и
  категорию
- `Product`: уникальный артикул, название, цена в тенге целым числом, остаток
  `quantity`, фото `imageUrl`, описание и совместимость с авто текстом
- `inStock` не хранится в базе — вычисляется в `src/lib/data.ts` как
  `quantity > 0`
- Индексы: уникальный по `Product.article` и обычный по `Product.name` для
  будущего быстрого поиска
- `User`: уникальный номер телефона в каноническом виде `+77001234567` (это
  логин), scrypt-хеш пароля, имя, город и адрес по умолчанию; email не
  обязателен и для входа не используется, пароль в открытом виде не хранится
- `Order` и `OrderItem`: имя, телефон, адрес или самовывоз, комментарий, статус
  (`new`, `in_progress`, `done`), дата; позиции хранят количество и цену на
  момент заказа
- `Order.userId` связывает заказ с аккаунтом; у гостевых заказов поле пустое,
  при удалении аккаунта заказы остаются с `userId = null`
- `ImportRun` хранит завершённые импорты: имя файла, счётчики и JSON-массив
  нормализованных артикулов — по нему работает обнуление остатков у товаров,
  которых не было в файле
- Файл `prisma/dev.db` и его служебные файлы в `.gitignore`; в репозитории
  лежат только схема, миграции и seed

## Оформление заказа

- `/checkout` отправляет заказ через server action; имя, телефон, email, способ
  получения, адрес для курьера и согласие проверяются на сервере
- В одной транзакции создаются `Order` со статусом `new` и `OrderItem` с ценой
  на момент заказа, после чего остаток `Product.quantity` уменьшается
- Заказать отсутствующий товар или количество больше остатка нельзя: сервер
  возвращает ошибку с названием товара и доступным количеством
- После успеха корзина очищается и открывается `/checkout/success?order=...` с
  номером заказа, статусом, адресом и составом
- Если клиент вошёл, имя, телефон и адрес подставляются из профиля, а заказ
  привязывается к аккаунту и появляется в `/account/orders`; гость заполняет
  контакты вручную, и его заказ доступен только по ссылке
- Телефон заказа показывается в списке и деталях заказа в кабинете, на странице
  подтверждения и в админке — всегда в читаемом виде `+7 (700) 000-00-00`
- Email, указанный при оформлении, сохраняется в заказе и виден в кабинете и
  админке; письма клиенту пока не отправляются
- Страница подтверждения проверяет владельца: чужой заказ клиента по прямой
  ссылке не откроется

## Аккаунты клиентов

- Регистрация на `/register`: имя, номер телефона и пароль от 8 символов;
  повторный номер отклоняется, пароль хранится как scrypt-хеш с солью
- Номер принимается в форматах `+7 (700) 000-00-00`, `8 700 000-00-00` или
  `700 000-00-00` и сохраняется в каноническом виде `+77000000000`
- Вход на `/login` по номеру телефона и паролю; неверные данные дают общий ответ
  «Неверный номер телефона или пароль», проверка пароля выполняется и для
  незарегистрированного номера, чтобы по времени ответа нельзя было определить
  наличие аккаунта
- Сессия — httpOnly-cookie `partshub_session` с HMAC-подписью на 1 день или на
  30 дней при включённом «Запомнить меня». Ключ подписи берётся из
  `SESSION_SECRET`, а если переменная не задана — из `ADMIN_PASSWORD`
- Layout `/account` без валидной сессии перенаправляет на `/login`; страницы
  заказов дополнительно проверяют владельца, поэтому история другого клиента
  недоступна
- Профиль `/account/profile` сохраняет имя, номер телефона, город и адрес в
  базе; номер можно сменить, если он не занят другим аккаунтом — восстановление
  пароля пока не реализовано
- Выход очищает cookie сессии и возвращает на главную

## Админка

- Вход на `/admin/login` по паролю из `ADMIN_PASSWORD`; неверный пароль даёт
  ошибку, без настроенного пароля вход запрещён
- Сессия — httpOnly-cookie на 8 часов, подписанная HMAC от пароля. Доступ
  проверяется дважды: `src/proxy.ts` до рендера отдаёт `307` на `/admin/login`,
  а layout и страницы повторно проверяют сессию — данные заказов не попадают
  в ответ анонимному посетителю
- На `/admin` видны счётчики заказов, новых заказов, товаров и позиций без
  остатка, а также списки заказов и товаров
- Товар можно добавить вручную на `/admin/products/new` и отредактировать на
  `/admin/products/[id]`: артикул, название, бренд, категория, цена, старая
  цена, остаток, единица, метка, совместимость и описание. Бренд и категория
  выбираются из подсказок или создаются по введённому имени; slug категории
  генерируется транслитерацией и проверяется на уникальность
- Артикул проверяется на дубликат без учёта регистра, пробелов и дефисов.
  Удалить можно только товар, которого нет в заказах; фото при удалении
  стирается с диска
- На `/admin/catalog` — справочники каталога: создание и переименование
  брендов, создание и редактирование категорий (название, короткое имя,
  иконка, порядок вывода, описание). Удалить можно только бренд или категорию
  без товаров; slug категории создаётся один раз и дальше не меняется
- Статус заказа (`new`, `in_progress`, `done`, `cancelled`) и остаток товара
  меняются через server actions с проверкой админ-сессии и обновлением страницы
- Отмена заказа возвращает его позиции на склад; возврат отменённого заказа в
  работу снова списывает остаток и блокируется, если товара уже не хватает.
  Повторная отмена остаток не удваивает
- В списке товаров можно загрузить, заменить или удалить фото позиции: JPG, PNG
  или WebP до 5 МБ. Тип проверяется по содержимому файла, а не по расширению;
  имя файла — UUID. Фото выводятся в карточках, таблице, корзине и на странице
  товара через `next/image`
- Файлы лежат в `storage/products` (каталог в `.gitignore`) и отдаются маршрутом
  `/uploads/products/<uuid>.<ext>` с `Cache-Control: immutable`; маршрут принимает
  только UUID-имена и не отдаёт файлы вне каталога
- Вход и выход защищены от CSRF встроенной проверкой origin Server Actions;
  для работы за прокси Codespaces origin разрешён в `next.config.ts`

## Ограничение частоты запросов

- Вход клиента: 10 попыток на пару «IP + номер телефона» за 15 минут
- Регистрация: 5 попыток с одного IP за час
- Оформление заказа: 10 заказов с одного IP за 10 минут
- Вход в админку: 10 попыток с одного IP за 15 минут
- При превышении возвращается сообщение с количеством секунд до следующей
  попытки; успешный вход в админку не сбрасывает счётчик
- IP берётся из `x-forwarded-for` (первый адрес) или `x-real-ip`, иначе
  используется `local`. За обратным прокси заголовок должен проставляться
  прокси, а не клиентом
- Счётчики хранятся в памяти процесса: они обнуляются при перезапуске и не
  общие для нескольких инстансов. Для горизонтального масштабирования нужен
  внешний store (Redis и т. п.)
- Карта счётчиков ограничена 5000 записями: просроченные удаляются, а при
  переполнении вытесняются самые старые, чтобы память не росла бесконечно

## Заголовки безопасности и индексация

- Все ответы получают `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`,
  `X-Frame-Options: SAMEORIGIN` и `Permissions-Policy` без камеры, микрофона
  и геолокации; заголовок `X-Powered-By` отключён
- `/robots.txt` разрешает индексацию сайта и закрывает `/admin`, `/account`,
  `/cart` и `/checkout`; сами страницы админки дополнительно отдают
  `noindex, nofollow`
- `sitemap.xml` пока не генерируется

## Страницы ошибок

- Несуществующий адрес отдаёт `/not-found` со статусом 404
- Ошибка рендера показывает `error.tsx` с кнопкой повтора и кодом ошибки;
  `global-error.tsx` страхует ошибки корневого layout
- `loading.tsx` показывает скелетон во время загрузки страницы
- Динамические страницы с PPR (товар, заказ) могут ответить 200 и показать
  404-контент, потому что оболочка уже отправлена; данные при этом не утекают
- `Header` и `BottomNav` используют `usePathname()`, поэтому в корневом layout
  они обёрнуты в `<Suspense>`: иначе PPR-предзагрузка и обновление после server
  actions отвечали 500 (`CLIENT_HOOK_DYNAMIC`), а страница админки зависала
  после загрузки фото

## Импорт прайс-листов

- Страница `/admin/import`, доступна только после входа в админку
- Форматы `.xlsx`, `.xls`, `.csv` (и `.xlsm`/`.txt`): кодировка (UTF-8,
  Windows-1251, UTF-16) и разделитель (запятая, точка с запятой, табуляция,
  `|`) определяются автоматически
- Строка заголовков ищется в первых 80 строках: пустые строки и шапка компании
  пропускаются; номер строки можно поправить вручную, лист выбирается из
  списка
- Колонки распознаются по названиям на русском, английском, транслите и
  китайском (артикул, название, цена, остаток, бренд, категория,
  совместимость, единица). Любое поле можно переназначить; сопоставление
  запоминается в localStorage по набору заголовков
- Цены очищаются от пробелов, запятых, `₸`, `$`, `¥`, «тг» и т. п.; остатки
  понимают «5 шт», «>10», «10+», «есть», «нет». Артикулы сравниваются без
  регистра, пробелов и дефисов
- Валюта файла, курс к тенге и наценка задаются до импорта; цена на сайте
  хранится в тенге
- Предпросмотр показывает, сколько добавится и обновится, строки с ошибками и
  причинами, дубликаты артикулов внутри файла с номерами строк, новые бренды и
  категории
- Запись идёт пакетами по 500 строк в транзакциях с прогресс-индикатором;
  отсутствующие в файле товары не удаляются
- После импорта доступна кнопка «Обнулить остаток у отсутствующих»: она ставит
  `quantity = 0` товарам, которых не было в последнем завершённом импорте
- Сессия импорта (файл и подготовленные строки) живёт в памяти процесса час;
  после перезапуска сервера файл нужно загрузить заново
- Ограничения: 25 МБ и 100 000 строк на файл; фотографии и характеристики не
  импортируются. На машине разработки 50 000 строк разбираются примерно за 2 с,
  запись в SQLite занимает около 19 с

- Цены в тенге, формат — через `formatPrice()`: `12 500 ₸`

## Оформление и адаптивность

- Один акцент — синий `#1D4ED8`; фон страниц светло-серый, карточки белые,
  текст — нейтральный тёмно-серый
- Акцент используется для главных кнопок, цен и активных элементов; зелёный и
  красный — только для статуса наличия товара
- Все цвета, радиусы и тени заданы токенами в `src/app/globals.css`
- Мобильная версия (360–430px): компактная шапка с бургер-меню и поиском,
  карточки в 2 колонки, фиксированная нижняя навигация, без горизонтального
  скролла страницы
- Десктоп (от 1024px): шапка в одну строку, контейнер 1280px, 4 карточки в ряд,
  фильтры левой колонкой, страница товара в две колонки

## Ограничения этапа

Онлайн-оплата, отзывы и оценки, подбор по VIN, баланс, карта пунктов выдачи и чат
поддержки не реализованы — подробнее в `docs/research/site-map.md`. Корзина и
избранное хранятся в браузере и не переносятся между устройствами. У аккаунтов
нет подтверждения номера телефона и восстановления пароля. Ограничения частоты
запросов хранятся в памяти процесса и не рассчитаны на несколько инстансов. Фото
товаров лежат на локальном диске: при нескольких инстансах или serverless нужно
S3-совместимое хранилище. Импорт прайс-листов держит сессию в памяти одного
процесса: для нескольких инстансов или serverless нужен внешний job-store.
Slug категории после создания не редактируется, чтобы не ломать ссылки; при
создании категории из формы товара она получает иконку `gear` и пустое
описание, которые можно исправить на `/admin/catalog`.
