# План разработки PartsHub

Каталог автозапчастей. Стек: Next.js (App Router, TypeScript), Tailwind CSS, Prisma + SQLite.

## Общие принципы

- Порт разработки — **3012**.
- Этапы 1–2 работают на тестовых данных, начиная с этапа 3 данные берутся из БД.
- Каждый этап завершается рабочей сборкой (`npm run build`) и ручной проверкой по списку.
- Название «PartsHub» — временное, замена на этапе брендирования.

## Этап 1. Каркас

- [x] Next.js (App Router, TypeScript) + Tailwind CSS.
- [x] Prisma + SQLite, первая миграция.
- [x] Общий layout: шапка с навигацией, подвал.
- [x] Пустые страницы `/`, `/catalog`, `/product/[id]`.
- [x] Запуск на порту 3012.
- [x] Название-заглушка «PartsHub».

**Готово, если:** `npm run dev` открывается на `http://localhost:3012`, все три маршрута отвечают 200, `npm run build` проходит без ошибок.

## Этап 2. Дизайн всех типов страниц на тестовых данных

- Карта типов страниц и раскладки — `docs/research/site-map.md`.
- Референс: autodoc.ru (только структура и раскладка, мобильная версия 390px, затем адаптив под десктоп).
- Свой бренд **PartsHub**, своя палитра: тёмно-синий `#14213D` + оранжевый акцент `#F28C28`, зелёный — только для наличия. Все цвета — Tailwind-токены в `src/app/globals.css`.
- Тестовые данные — `src/lib/mock-data.ts` (12 товаров), изображения — собственные SVG-заглушки.
- Общие компоненты: Header, SideMenu, BottomNav, Footer, ProductCard, ProductTable, FilterSheet, CartItem, AccountNav и UI-примитивы.
- Маршруты:
  - главная `/`;
  - каталог `/catalog`, категория со списком и фильтрами `/catalog/[slug]`;
  - товар `/product/[id]`;
  - поиск `/search`;
  - корзина `/cart`, оформление `/checkout`, успех `/checkout/success`;
  - вход `/login`, регистрация `/register`;
  - кабинет `/account`, профиль `/account/profile`, заказы `/account/orders` и `/account/orders/[id]`, избранное `/account/favorites`, уведомления `/account/notifications`;
  - «Клиентам» `/for-customers`, «Компания» `/company`, «Обратная связь» `/feedback`.
- Каталог: переключатель «карточки / таблица», фильтры в боковой панели (десктоп) и нижнем листе (мобильный).
- Состояния: пустая корзина, пустое избранное, пустой результат фильтров и поиска, отправленные формы.
- Без БД: корзина и избранное живут в клиентском контексте, формы показывают локальный результат.
- Убраны оценки, отзывы, VIN и баланс; «Доставка от 1 дня» заменена на «Со склада».
- Внутренние ссылки между страницами рабочие.

**Готово, если:** все перечисленные маршруты отвечают 200, корректно выглядят на 390px и десктопе, переключатель «карточки / таблица» и фильтры работают на мок-данных, `npm run build` проходит без ошибок.

## Этап 3. БД и товары через Prisma

- Схема: категории, товары, изображения, характеристики.
- Миграции и seed-скрипт с реальными тестовыми товарами.
- Замена мок-данных на запросы через Prisma.
- Серверный слой доступа к данным (`src/lib/db.ts`).

**Готово, если:** данные страниц совпадают с содержимым SQLite, seed пересоздаёт БД одной командой.

## Этап 4. Поиск и фильтры

- Поиск по названию, артикулу и описанию.
- Фильтры: категория, бренд, цена, наличие.
- Сортировка и пагинация.
- Состояние фильтров в URL-параметрах.

**Готово, если:** фильтры комбинируются, ссылка с параметрами воспроизводит выдачу, пустой результат обрабатывается.

## Этап 5. Вход клиентов и кабинет

- Регистрация и вход по email и паролю, хеширование паролей.
- Сессия в cookie, защита маршрутов кабинета.
- Кабинет: профиль, контактные данные, история заказов.

**Готово, если:** пользователь регистрируется, входит, выходит; кабинет недоступен без сессии.

## Этап 6. Корзина и заказы

- Корзина: добавление, изменение количества, удаление, итог.
- Оформление заказа: контакты, адрес, способ доставки.
- Заказы: сохранение, номер, статусы, страница заказа.

**Готово, если:** оформленный заказ сохраняется в БД и виден в кабинете.

## Этап 7. Админка

- Роли пользователей (администратор, клиент).
- CRUD товаров, категорий и характеристик.
- Список заказов и смена статуса.
- Защита всех админ-маршрутов.

**Готово, если:** администратор управляет каталогом и заказами из интерфейса, клиент не имеет доступа.

## Этап 8. Импорт Excel

- Загрузка `.xlsx` с товарами.
- Сопоставление колонок, валидация строк.
- Отчёт об ошибках, частичный импорт.
- Обновление существующих товаров по артикулу.

**Готово, если:** файл импортируется, некорректные строки не ломают процесс и попадают в отчёт.

## Этап 9. ИИ-поиск

- Поиск запросов на естественном языке («тормозные колодки на Camry 2018»).
- Извлечение параметров запроса и подбор товаров.
- Fallback на обычный поиск при ошибке.

**Готово, если:** типовые естественные запросы дают релевантную выдачу, расход API ограничен.

## Этап 10. PWA

- `manifest.json`, иконки, тема.
- Service worker: кеширование статических ресурсов и офлайн-страницы.
- Установка на мобильные устройства.

**Готово, если:** приложение устанавливается, открывается офлайн в пределах кеша.

## Этап 11. Безопасность и деплой

- Валидация входных данных, rate limiting, CSRF-защита.
- Security-заголовки, HTTPS, защита секретов.
- Продакшен-БД и переменные окружения.
- Домен, мониторинг, резервные копии.

**Готово, если:** приложение доступно на домене, аудит зависимостей и проверка заголовков пройдены.
